# ИИ-фитнес-тренер: мобильная страница + Telegram-бот

Два входа в один аккаунт:

* **Веб-страница под телефон** — регистрация по номеру или почте с кодом
  подтверждения, короткий опрос и готовый план тренировок сразу на экране.
* **Telegram-бот** — напоминания, журнал тренировок, чат с ИИ-тренером и
  оплата подписки.

Тренироваться можно **дома, в зале или миксом** — в миксе тяжёлые дни идут в
зале, лёгкие дома, и каждый день помечен местом.

Бесплатный тариф — программа, напоминания и журнал. Pro — питание, аналитика,
программа на 4 недели и безлимитный чат; оплата через Telegram Stars, без
платёжного провайдера и банковской карты.

## Что умеет

### Free — бесплатно и без ограничений по времени

| Функция | Описание |
|---|---|
| Регистрация | По номеру телефона или почте с кодом подтверждения — на сайте, или прямо в боте |
| Профиль | Пол, возраст, рост, вес, цель, уровень, место тренировок, дни в неделю, часовой пояс |
| Программа | Генератор подбирает сплит, упражнения, подходы и отдых под цель и место — 1 неделя |
| Место занятий | Дома, в зале, микс (зал/дом через день) или совсем без оборудования |
| Тренировка на сегодня | Ротация по дням сплита с разминкой, заминкой и оценкой длительности |
| Напоминания | Настраиваются на последнем шаге регистрации: 1 напоминание о тренировке в дни твоего сплита и в твоём часовом поясе |
| Журнал | Отметка тренировки с оценкой тяжести, счётчик за неделю и за всё время |
| Вес | `/weight 78.5` — запись замеров |
| ИИ-тренер | 5 вопросов в день |

### Pro — по подписке

| Функция | Описание |
|---|---|
| Программа на 4 недели | Прогрессия по неделям + адаптация под профиль через LLM |
| Безлимитный чат | Без дневного лимита сообщений |
| Питание | BMR/TDEE по Миффлину — Сан-Жеору, калории и БЖУ под цель, пример меню |
| Напоминания | До 10: тренировка, вода, взвешивание, свой текст |
| Аналитика | Тренировки за 7/30 дней, серия недель, лучшая неделя, динамика веса |
| Экспорт | Выгрузка профиля, программы, тренировок и замеров в JSON |

Тариф проверяется в одном месте — `subscription.py`. Чтобы перенести функцию
между тарифами, достаточно поменять состав `FREE_PLAN.features` /
`PRO_PLAN.features`.

## Веб-регистрация

Путь пользователя на телефоне: **контакт → код → 7 шагов опроса → план**.

1. Вводит номер телефона или почту — пароля нет, приходит одноразовый код.
2. Подтверждает код (6 цифр, 10 минут, 5 попыток).
3. Проходит опрос: пол, возраст/рост/вес, цель, уровень, **где тренироваться
   (дома / в зале / микс / без оборудования)**, количество тренировок, время
   напоминания. Часовой пояс страница определяет сама.
4. Получает план: карточки тренировок с подходами, отдыхом и длительностью, а
   для микса — с пометкой места на каждый день.
5. По кнопке «Подключить Telegram» аккаунт связывается с ботом, и напоминания
   начинают приходить в мессенджер.

Страница — один файл без сборки и внешних запросов: адаптив под мобильные,
тёмная тема по системной настройке, работает в любом браузере.

### Безопасность входа

| Что | Как сделано |
|---|---|
| Хранение кодов | Только HMAC-SHA256, привязанный к идентификатору; сравнение — constant-time |
| Жизнь кода | 10 минут, 5 попыток ввода, одноразовый — после успеха сжигается |
| Антиспам | Повтор не чаще 60 сек, не больше 5 кодов в час на контакт, лимит по IP |
| Перебор аккаунтов | Регистрация и вход — один и тот же ответ, по нему нельзя узнать, есть ли аккаунт |
| Сессии | Подписанный HMAC-токен с сроком жизни, секрет в `FITNESS_SECRET_KEY` |
| Заголовки | CSP без внешних источников, `X-Frame-Options: DENY`, `nosniff` |
| Утечка кода в ответ API | Только при `FITNESS_DEV_SHOW_CODE=1` и только когда провайдер не настроен |

Доставка кодов подключается через SMTP (почта) и HTTP-вебхук (SMS — подойдёт
любой шлюз, принимающий `{"phone": ..., "text": ...}`). Без настройки код
пишется в лог — так весь сценарий можно прогнать локально без провайдера.

## Быстрый старт

```bash
# 1. Токен бота у @BotFather (для бота; веб может работать и без него)
export TELEGRAM_BOT_TOKEN="123456:ABC-..."
export FITNESS_BOT_USERNAME="my_fitness_bot"

# 2. Секрет для сессий — сгенерируй один раз и сохрани
export FITNESS_SECRET_KEY="$(python -c 'import secrets;print(secrets.token_urlsafe(32))')"

# 3. (необязательно) ИИ-бэкенд — любой OpenAI-совместимый эндпоинт
export FITNESS_LLM_API_KEY="sk-..."

# 4. Запуск: бот и веб в одном процессе
uv run python -m fitness_coach          # страница на http://localhost:8080
```

Только страница — `FITNESS_BOT_ENABLED=0`, только бот — `FITNESS_WEB_ENABLED=0`.
Для локальной проверки регистрации без SMS-провайдера: `FITNESS_DEV_SHOW_CODE=1`.

### API

| Метод | Назначение |
|---|---|
| `POST /api/auth/request` | Запросить код на телефон или почту |
| `POST /api/auth/verify` | Подтвердить код, получить токен сессии |
| `GET /api/me` | Профиль, тариф, напоминания |
| `POST /api/survey` | Ответы опроса → сохранение профиля и план |
| `GET /api/plan` | Актуальный план (+ питание и аналитика на Pro) |
| `POST /api/telegram/link` | Одноразовый код и диплинк для привязки бота |
| `GET /healthz` | Проверка живости для Railway |

Без `FITNESS_LLM_API_KEY` бот полностью работоспособен: тренер отвечает из
встроенной базы знаний (белок, крепатура, плато, разминка, кардио, сон,
мотивация), а при вопросах про боль и травмы — отправляет к врачу.

Все переменные окружения перечислены в [`.env.example`](.env.example).

## Оплата подписки

Используются **Telegram Stars** (`currency: XTR`): провайдерский токен не нужен,
работает во всех странах, где доступен Telegram.

Поток оплаты:

1. `/subscribe` → экран с составом Pro и кнопкой оплаты;
2. `sendInvoice` на `FITNESS_PRO_PRICE_STARS` звёзд;
3. `pre_checkout_query` подтверждается только для актуального payload;
4. `successful_payment` → подписка на `FITNESS_PRO_PERIOD_DAYS` дней.

Повторная покупка при активной подписке **продлевает** её, а не обнуляет.
`telegram_payment_charge_id` пишется в таблицу с уникальным индексом, поэтому
повторная доставка апдейта от Telegram не выдаст второй месяц.

Кроме оплаты, Pro можно выдать:

- промокодом — `/promo КОД`, коды задаются в `FITNESS_PROMO_CODES`,
  одноразовые для каждого пользователя;
- вручную — `/grant <telegram_id> [дней]` от аккаунта из `FITNESS_ADMIN_IDS`
  (без числа дней выдаётся бессрочный доступ).

## Напоминания

Напоминание не нужно настраивать вручную: последний шаг регистрации — выбор
времени, а дни берутся из профиля. 3 тренировки в неделю → Пн/Ср/Пт,
4 → Пн/Вт/Чт/Пт, 5 → будни, 2 → Пн/Чт, то есть пинги совпадают с днями
сгенерированного сплита. Можно выбрать своё время или отказаться — тогда
включить их получится позже через `/reminders`. Повторный `/start` не плодит
дубликаты: у существующего напоминания просто меняется время.

Пользователь задаёт время в своём часовом поясе; в базе хранится абсолютная
метка следующего срабатывания (`next_fire_at`). Планировщик раз в
`FITNESS_REMINDER_TICK` секунд забирает всё, что просрочено, отправляет и сразу
пересчитывает следующий запуск.

Что учтено:

- смена часового пояса пересчитывает все напоминания пользователя;
- напоминание переносится даже при ошибке отправки, поэтому один сбой не
  «залипает» в очереди;
- если пользователь заблокировал бота (403), напоминание выключается, а не
  ретраится вечно;
- выключенное и снова включённое напоминание не срабатывает мгновенно на
  устаревшей метке.

## Архитектура

```
fitness_coach/
├── config.py         настройки из переменных окружения
├── models.py         доменные датаклассы
├── storage.py        SQLite: пользователи, напоминания, логи, платежи, квоты
├── subscription.py   тарифы, лимиты и проверка доступа к функциям
├── workouts.py       генератор программ (детерминированный, без ИИ)
├── nutrition.py      расчёт калорий и БЖУ
├── analytics.py      статистика прогресса и экспорт
├── coach.py          ИИ-тренер + офлайн-база знаний
├── scheduler.py      расчёт времени напоминаний и фоновый цикл
├── telegram_api.py   клиент Bot API на aiohttp
├── payments.py       Telegram Stars, промокоды, выдача Pro
├── keyboards.py      inline-клавиатуры
├── texts.py          все тексты интерфейса
├── bot.py            роутинг апдейтов и машина состояний диалогов
├── webapp/
│   ├── auth.py       одноразовые коды, лимиты, токены сессий
│   ├── delivery.py   доставка кодов: SMTP, SMS-вебхук, лог
│   ├── server.py     HTTP API и отдача страницы
│   └── static/       мобильная страница (один файл, без сборки)
└── smoke_e2e.py      сквозной прогон против локальной заглушки Bot API
```

Зависимости — только `aiohttp` (уже есть в проекте) и стандартная библиотека.
База — SQLite, файл задаётся `FITNESS_DB_PATH`.

Генератор программ намеренно не зависит от LLM: бесплатный тариф работает без
ключей, ответы воспроизводимы и покрыты тестами, а для Pro тот же черновик
отдаётся модели на персонализацию.

## Проверка работы

Два уровня, оба без токена и без обращений к api.telegram.org.

**Юнит-тесты** — быстро, на каждое изменение:

```bash
uv run pytest tests/test_fitness_core.py tests/test_fitness_bot.py -q
```

187 тестов: авторизация по коду (хранение хэшей, срок жизни, лимиты, перебор,
подмена токена), валидация анкеты, HTTP API, чередование зал/дом в миксе,
связка веб-аккаунта с Telegram без потери данных, расчёты (калории, БЖУ, время срабатывания напоминаний в разных
часовых поясах), гейтинг тарифов, идемпотентность платежей, изоляция данных
между пользователями и сквозные сценарии диалогов на фейковом Bot API.

**Сквозной прогон** — перед деплоем:

```bash
uv run python -m fitness_coach.smoke_e2e             # 64 проверки
uv run python -m fitness_coach.smoke_e2e --transcript # + вся переписка
```

Здесь внутри бота не подменено ничего: работает настоящий `bot.run()` с long
polling, реальные HTTP-запросы через aiohttp, сохранение offset и фоновый
планировщик напоминаний — подменён только сервер Telegram на локальную
заглушку. Сценарий проходит путь живого пользователя: регистрация → создание
напоминания по профилю → тренировка и журнал → вопросы тренеру и упор в лимит
Free → закрытые Pro-функции → оплата Stars с подтверждением pre-checkout и
повторной доставкой апдейта → открывшиеся Pro-функции → реальная отправка
напоминания планировщиком → **регистрация на сайте по телефону с настоящими
HTTP-запросами, опрос, план-микс, привязка к боту по диплинку и напоминание,
дошедшее в привязанный Telegram**. Возвращает код 0 при успехе, поэтому годится как
гейт в CI или перед `railway up`.

## Деплой на Railway

В репозитории уже лежит всё необходимое: [`railway.json`](../railway.json) в
корне и [`Dockerfile`](Dockerfile). Образ ставит только `aiohttp`, поэтому
тяжёлые зависимости основного проекта в сборку не попадают.

### Через веб-интерфейс

1. **New Project → Deploy from GitHub repo** → выбери этот репозиторий и ветку.
2. Railway подхватит `railway.json` и соберёт по `fitness_coach/Dockerfile`.
3. **Variables** — задай переменные:

   | Переменная | Значение |
   |---|---|
   | `TELEGRAM_BOT_TOKEN` | токен от @BotFather (обязательно) |
   | `FITNESS_LLM_API_KEY` | ключ OpenAI-совместимого API (опционально) |
   | `FITNESS_LLM_MODEL` | например `gpt-4o-mini` |
   | `FITNESS_PRO_PRICE_STARS` | цена подписки в звёздах, по умолчанию 250 |
   | `FITNESS_PRO_PERIOD_DAYS` | срок подписки, по умолчанию 30 |
   | `FITNESS_PROMO_CODES` | промокоды через запятую |
   | `FITNESS_ADMIN_IDS` | твой Telegram id для `/stats` и `/grant` |
   | `FITNESS_SECRET_KEY` | секрет для сессий (обязательно, иначе логаут на каждом рестарте) |
   | `FITNESS_BOT_USERNAME` | username бота без @ — для кнопки «Подключить Telegram» |
   | `FITNESS_SMTP_*` | доставка кодов на почту |
   | `FITNESS_SMS_WEBHOOK_URL` | доставка кодов по SMS |

4. **Volumes → New Volume**, mount path `/data`. Без тома база SQLite живёт
   внутри контейнера и обнуляется при каждом деплое. `FITNESS_DB_PATH` уже
   указывает на `/data/bot.sqlite3`.
5. Deploy. В логах должно появиться `Bot started, polling from offset ...`.

### Через CLI

```bash
npm i -g @railway/cli
railway login
railway init                       # или railway link к существующему проекту
railway volume add --mount-path /data
railway variables --set TELEGRAM_BOT_TOKEN=123456:ABC-...
railway up
railway logs
```

### Важно

- **Ровно одна реплика.** Бот работает через long polling: два инстанса начнут
  тянуть `getUpdates` одновременно и получат 409 Conflict. В `railway.json`
  зафиксировано `numReplicas: 1` — не увеличивай.
- **Не включай Sleep/Serverless.** Спящий сервис не отправит напоминание;
  `sleepApplication: false` уже прописан.
- **Публичный домен нужен** — на нём живёт страница регистрации. Railway
  сам подставит `PORT`, healthcheck настроен на `/healthz`.
- Смещение апдейтов хранится в базе, поэтому редеплой не приводит к повторной
  обработке платежей и вопросов — при условии, что том подключён.

## Развёртывание на своём сервере

Бот работает через long polling, вебхук и белый IP не нужны — хватит любой
машины с Python 3.12:

```ini
# /etc/systemd/system/fitness-coach.service
[Unit]
Description=AI fitness coach telegram bot
After=network-online.target

[Service]
WorkingDirectory=/opt/fitness-coach
EnvironmentFile=/opt/fitness-coach/.env
ExecStart=/usr/bin/env uv run python -m fitness_coach
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Смещение апдейтов сохраняется в базе после каждого обработанного апдейта,
поэтому перезапуск не приводит к повторной обработке платежа или вопроса.

## Ограничения

Бот даёт общие рекомендации по тренировкам и питанию и не заменяет врача.
Вопросы про боль, травмы и хронические заболевания перенаправляются к
специалисту, расчёт калорий ограничен снизу безопасным минимумом, а советы по
препаратам и жёстким голоданиям исключены на уровне системного промпта.
